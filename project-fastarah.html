專案介紹Overview

Fastarah 像是幫商家請了一組 AI 行銷團隊。使用者在聊天室交辦工作，幾位有名字、有分工的 AI 員工會先互相討論，再由負責的那一位執行，過程中的任務、交接與卡關的地方都即時看得到。工作也可以用一句話排程，例如「每週一早上 9 點整理競品動態」；綁定 LINE 或 Telegram 後，用手機就能交辦與收成品。接上店家的客服帳號後，AI 還會依品牌資料回覆顧客，答不了就轉給真人並通知店家。

Fastarah is like hiring an AI marketing team. Users assign work in a chat room; named AI employees with distinct roles discuss it first, then the owner executes, with every task, hand-off and blocker visible in real time. Work can be scheduled in one sentence, such as “summarize competitor news every Monday at 9am”, and once LINE or Telegram is linked, tasks can be assigned and results received from a phone. Connected to a shop’s messaging accounts, the AI also answers customers from brand data and escalates to a human when it cannot.

我負責的部分My role

產品原本是只在一台主機上執行的單機版，資料庫與檔案也都放在同一台機器上，沒辦法支撐多人同時使用。我負責把它改造成能讓 50 人同時使用、而且故障時能自己恢復的雲端架構，並實際驗證。

The product ran as a single-machine app with its database and files on the same host, and could not support many users at once. I was responsible for turning it into a cloud architecture that supports 50 concurrent users and recovers on its own from failures, and for validating it.

具體貢獻What I did

  1. 重新設計 AWS 架構Redesigning the AWS architecture

    把單機版拆成一台控制機，加上可依用量自動增減的工作機。

    Split the app into a control node plus workers that scale automatically with demand.

  2. 資料搬遷與環境程式碼化Data migration and infrastructure as code

    資料庫從 SQLite 搬到 PostgreSQL、檔案搬到 S3，並用程式碼（AWS CDK）定義整套環境。

    Migrated the database from SQLite to PostgreSQL and files to S3, and defined the whole environment as code with AWS CDK.

  3. 故障演練Failure drills

    在測試環境強制切換資料庫、關掉主機、模擬整個機房區域失效，三種情境下系統都在 3 分鐘內自動恢復。

    In staging, forced a database failover, terminated hosts and simulated a zone outage; the system recovered on its own in under 3 minutes each time.
